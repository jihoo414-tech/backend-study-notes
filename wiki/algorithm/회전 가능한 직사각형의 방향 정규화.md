# 회전 가능한 직사각형의 방향 정규화

## 한눈에 보기

프로그래머스 `최소직사각형`의 핵심은 모든 명함의 회전 조합을 실제로 열거하는 것이 아니다. 각 명함을 독립적으로 돌릴 수 있으므로 먼저 방향을 다음처럼 통일한다.

```text
(원래 가로, 원래 세로)
→ (긴 변, 짧은 변)
```

모든 명함을 같은 규칙으로 정규화한 뒤 `긴 변들의 최댓값 × 짧은 변들의 최댓값`을 구하면 모든 명함이 들어가는 최소 지갑의 넓이가 된다.

## 왜 필요한가

명함마다 회전 여부가 두 가지이므로 그대로 생각하면 명함 `N`장에 대해 최대 `2^N`개의 배치를 떠올리기 쉽다. 그러나 이 문제에서 각 명함의 회전은 다른 명함의 방향 선택에 제약을 주지 않는다. 또한 지갑의 두 축 이름인 `가로`와 `세로`는 서로 바꿔도 넓이가 같다.

따라서 회전 조합을 전부 비교하기 전에 각 원소를 동일한 표현으로 바꿀 수 있는지 살피는 것이 핵심이다. 이처럼 여러 표현이 사실상 같은 상태라면 하나의 표준 형태로 바꾸는 것을 **정규화**라고 볼 수 있다.

## 핵심 개념

### 1. 먼저 가장 단순한 완전탐색을 적는다

명함마다 다음 두 선택이 있다.

```text
(w, h) 그대로 둔다.
(h, w) 회전한다.
```

처음에는 모든 조합을 고른 뒤 각 배치에서 다음 넓이를 계산한다고 생각할 수 있다.

```text
배치 넓이 = 배치된 가로들의 최댓값 × 배치된 세로들의 최댓값
```

이 출발점이 잘못된 것은 아니다. 다만 `2^N`을 그대로 구현하기 전에 중복되는 선택을 제거할 수 있는지 확인해야 한다.

### 2. 가로·세로 대신 긴 변·짧은 변으로 이름을 바꾼다

문제의 명함은 돌릴 수 있으므로 입력의 첫 번째 값이 끝까지 가로일 필요가 없다. 각 명함에 변하지 않는 정보는 다음 두 값이다.

```java
int longer = Math.max(size[0], size[1]);
int shorter = Math.min(size[0], size[1]);
```

모든 긴 변을 지갑의 한 축으로, 모든 짧은 변을 다른 축으로 보내면 방향 선택 기준이 하나로 통일된다.

### 3. 왜 이 방향이 최소인가

지갑의 두 변도 편의상 `긴 축 A`, `짧은 축 B`로 두고 `A >= B`라고 하자. 어떤 명함의 긴 변을 `long`, 짧은 변을 `short`라고 하면 그 명함이 지갑에 들어가기 위해 반드시 다음을 만족해야 한다.

```text
long <= A
short <= B
```

긴 변을 지갑의 짧은 축으로 보내면 짧은 축 `B`를 더 크게 만들어야 하며, 반대 축을 줄이는 이득도 생기지 않는다. 따라서 모든 명함에 대해 긴 변을 같은 축에 두어도 최적해를 잃지 않는다.

결국 가능한 모든 지갑은 적어도 다음 크기 이상이어야 한다.

```text
A >= 모든 명함의 long 중 최댓값
B >= 모든 명함의 short 중 최댓값
```

두 하한값을 그대로 선택한 지갑이 실제로 모든 명함을 수납하므로 이것이 최소 크기다.

### 4. 완전탐색 분류를 구현 방식으로 오해하지 않는다

문제 분류가 완전탐색이라고 해서 반드시 모든 회전 조합을 코드로 만들어야 하는 것은 아니다. 이 문제는 가능한 선택을 생각하는 데서 출발하지만, 대칭과 독립성을 관찰해 각 선택을 표준 방향 하나로 축약한다.

```text
모든 회전 조합을 생각한다
→ 가로·세로 이름은 교환 가능함을 발견한다
→ 각 명함을 (긴 변, 짧은 변)으로 통일한다
→ 한 번 순회하며 두 최댓값만 구한다
```

## 동작 원리

예제의 각 명함을 정규화하면 다음과 같다.

| 원본 | 긴 변 | 짧은 변 |
| --- | ---: | ---: |
| `(60, 50)` | 60 | 50 |
| `(30, 70)` | 70 | 30 |
| `(60, 30)` | 60 | 30 |
| `(80, 40)` | 80 | 40 |

- 긴 변의 최댓값: `80`
- 짧은 변의 최댓값: `50`
- 최소 넓이: `80 × 50 = 4000`

## 예제

사용자의 원본 코드는 올바른 원리를 구현한다. 다만 `minH`에는 최솟값이 아니라 **각 명함의 짧은 변들 중 최댓값**이 들어가므로 이름을 바꾸면 의도가 선명해진다.

```java
class Solution {
    public int solution(int[][] sizes) {
        int maxLong = 0;
        int maxShort = 0;

        for (int[] size : sizes) {
            int longer = Math.max(size[0], size[1]);
            int shorter = Math.min(size[0], size[1]);

            maxLong = Math.max(maxLong, longer);
            maxShort = Math.max(maxShort, shorter);
        }

        return maxLong * maxShort;
    }
}
```

명함 수를 `N`이라 하면 각 명함을 한 번만 확인하므로 시간 복잡도는 `O(N)`, 추가 공간 복잡도는 `O(1)`이다. 각 변의 최댓값이 1,000이므로 넓이는 최대 1,000,000이며 Java `int` 범위에 들어간다.

## 발상을 연습하는 질문

비슷한 문제를 만났을 때 다음 순서로 질문한다.

1. 각 원소마다 가능한 선택은 무엇인가?
2. 모든 선택을 열거하면 경우의 수가 얼마인가?
3. 선택 순서나 축 이름을 바꿔도 결과가 같은 대칭이 있는가?
4. 각 원소의 여러 표현을 하나의 표준 형태로 바꿀 수 있는가?
5. 정규화한 뒤 합계·최댓값·최솟값 중 무엇만 모으면 되는가?

이 문제에서 답은 다음과 같다.

```text
회전 여부 2가지
→ 2^N 조합
→ 지갑의 두 축은 서로 교환 가능
→ 각 명함을 (긴 변, 짧은 변)으로 정규화
→ 두 열의 최댓값만 집계
```

## 주의사항

- 입력의 `size[0]`을 항상 가로라고 고정하면 회전 가능 조건을 활용하지 못한다.
- `Math.min()`으로 구한 짧은 변도 전체에서는 최댓값을 구해야 모든 명함이 들어간다.
- 변수 이름은 계산 과정이 아니라 값의 의미를 나타내도록 `maxLong`, `maxShort`처럼 정한다.
- 완전탐색이라는 분류는 사고의 출발점일 뿐, 지수 시간 구현을 강제하지 않는다.
- 프로그래머스 제출 결과가 제공되지 않았으므로 전체 테스트 통과 여부는 아직 확인되지 않았다.
