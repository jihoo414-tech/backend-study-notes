# 정렬된 두 배열 병합과 투 포인터

## 한눈에 보기

두 입력 배열이 이미 정렬되어 있다면 모든 값을 다시 정렬할 필요가 없다. 각 배열의 아직 처리하지 않은 첫 원소를 가리키는 포인터 두 개를 두고, 두 원소 중 작은 값을 결과에 추가하면 된다.

이 문제의 핵심 신호는 **배열이 두 개라는 사실보다 두 배열이 모두 정렬되어 있다는 조건**이다. 정렬 상태 덕분에 현재 두 원소 중 작은 값은 남은 모든 값 가운데 가장 작다고 확정할 수 있다.

## 왜 필요한가

두 배열을 합친 뒤 다시 정렬하는 방법도 정답을 만들 수 있다. 그러나 원소 수를 각각 `N`, `M`이라고 할 때 이 방법은 보통 `O((N + M) log(N + M))`이 걸리며, 입력에 이미 존재하는 정렬 정보를 활용하지 않는다.

투 포인터 병합은 각 원소를 한 번만 결과로 옮기므로 `O(N + M)`에 끝난다. 병합 정렬의 병합 단계도 같은 원리를 사용한다.

## 핵심 발상

문제에서 다음 조건이 보이면 투 포인터를 후보로 생각한다.

- 정렬된 배열이나 리스트가 두 개 주어진다.
- 두 입력을 순서에 맞게 합치거나 공통 원소를 찾아야 한다.
- 각 입력에서 이미 지나간 원소로 돌아갈 필요가 없다.
- 포인터 중 적어도 하나를 매 반복마다 앞으로 이동시킬 수 있다.

단순히 “배열이 두 개면 투 포인터”가 아니다. **정렬 또는 단조성이 있어서 현재 판단 뒤에 탐색 범위를 안전하게 줄일 수 있는가**가 선택 기준이다.

## 동작 원리와 불변식

`p1`과 `p2`는 각 배열에서 아직 결과에 넣지 않은 첫 번째 원소를 가리킨다.

1. `arr1[p1]`과 `arr2[p2]`를 비교한다.
2. 더 작은 값을 결과에 추가하고 그 배열의 포인터만 한 칸 이동한다.
3. 한 배열을 모두 소비할 때까지 반복한다.
4. 다른 배열에 남은 값은 이미 정렬되어 있으므로 그대로 결과 뒤에 붙인다.

반복 중에는 다음 불변식이 유지된다.

> 결과 리스트에는 두 배열에서 지금까지 소비한 원소가 모두 들어 있으며, 항상 오름차순이다. 두 포인터 앞쪽의 원소는 이미 처리되었고 다시 확인할 필요가 없다.

현재 두 값 중 작은 값을 확정할 수 있는 이유는 각 포인터 뒤에 있는 값들이 현재 값보다 작지 않기 때문이다.

## 예제 추적

입력이 `[1, 3, 5]`, `[2, 3, 6, 7, 9]`라면 다음처럼 진행한다.

| `arr1[p1]` | `arr2[p2]` | 선택 | 결과 |
| --- | --- | --- | --- |
| 1 | 2 | 1 | `[1]` |
| 3 | 2 | 2 | `[1, 2]` |
| 3 | 3 | 두 번째 배열의 3 | `[1, 2, 3]` |
| 3 | 6 | 첫 번째 배열의 3 | `[1, 2, 3, 3]` |
| 5 | 6 | 5 | `[1, 2, 3, 3, 5]` |

첫 번째 배열이 끝나면 두 번째 배열의 `6, 7, 9`를 그대로 붙인다.

## 복잡도

- 시간 복잡도: `O(N + M)`
- 결과를 포함한 공간 복잡도: `O(N + M)`
- 결과 저장 공간을 제외한 보조 공간: `O(1)`

`O(N)`이라고만 쓰면 두 배열의 크기가 다를 때 의미가 불분명하므로 `O(N + M)`으로 쓰는 편이 정확하다. 두 배열을 합친 뒤 정렬하는 비교 대상도 `O(N²)`이 아니라 일반적으로 `O((N + M) log(N + M))`이다.

## 구현에서 확인할 점

사용자 풀이에서는 두 값이 같을 때 `else`로 두 번째 배열의 값을 먼저 넣는다. 다음 반복에서 첫 번째 배열의 같은 값도 들어가므로 중복은 빠지지 않는다. 문제는 두 배열 사이의 안정적인 선후 관계를 요구하지 않으므로 이 동작은 결과에 영향을 주지 않는다.

```java
while (p1 < n && p2 < m) {
    if (arr1[p1] < arr2[p2]) {
        answer.add(arr1[p1++]);
    } else {
        answer.add(arr2[p2++]);
    }
}
```

`ArrayList<Integer>`는 결과 크기만큼 박싱된 객체를 저장한다. 이 문제의 제한에서는 충분하지만, 원시 타입과 고정 크기 결과가 중요하다면 길이가 `N + M`인 `int[]`도 사용할 수 있다. 컬렉션 선택 기준은 [List와 Map 선택 기준](../java/List%EC%99%80%20Map%20%EC%84%A0%ED%83%9D%20%EA%B8%B0%EC%A4%80.md)과 연결된다.

## 실수하기 쉬운 부분

- 주 반복문의 조건을 `p1 < n || p2 < m`으로 쓰고 양쪽 원소에 무조건 접근하면 범위를 벗어날 수 있다.
- 한 배열이 끝난 뒤 다른 배열의 남은 원소를 누락할 수 있다.
- 값이 같을 때 두 값을 모두 건너뛰면 중복 원소가 사라진다.
- 정렬되지 않은 입력에도 같은 방식이 동작한다고 일반화하면 안 된다.
- 포인터가 매 반복에서 전진하지 않는 분기를 만들면 무한 루프가 생길 수 있다.

## 발상을 복원하는 질문

풀이가 바로 떠오르지 않을 때 다음 순서로 묻는다.

1. 입력이 이미 정렬되어 있다는 조건으로 무엇을 확정할 수 있는가?
2. 아직 보지 않은 값 중 최솟값 후보는 어디에 있는가?
3. 현재 비교에서 어느 쪽 포인터를 버려도, 즉 다시 보지 않아도 안전한가?
4. 매 반복에서 포인터가 전진한다면 전체 원소를 몇 번 방문하는가?
5. 한쪽 포인터가 끝난 뒤 남은 구간은 어떤 상태인가?
