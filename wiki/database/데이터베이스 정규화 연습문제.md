# 데이터베이스 정규화 연습문제

## 문제: 온라인 강의 수강 신청

온라인 강의 서비스가 수강 신청 정보를 다음 테이블 하나에 저장하고 있다.

### 업무 규칙

1. 학생은 여러 강좌를 수강할 수 있고, 강좌에는 여러 학생이 참여할 수 있다.
2. 한 학생은 같은 강좌를 최대 한 번만 신청할 수 있다.
3. 학생은 연락처를 여러 개 등록할 수 있다.
4. 강좌 하나는 강사 한 명이 담당한다. 강사는 여러 강좌를 담당할 수 있다.
5. 강좌는 카테고리 하나에 속한다. 카테고리에는 여러 강좌가 속할 수 있다.
6. 점수는 아직 평가되지 않은 경우 `NULL`일 수 있다.

### 정규화 전 테이블

`COURSE_ENROLLMENT_RAW`

| student_id | student_name | student_email    | student_phones               | course_id | course_name | course_fee | instructor_id | instructor_name | instructor_email | category_id | category_name | enrolled_at |  score |
| ---------: | ------------ | ---------------- | ---------------------------- | --------: | ----------- | ---------: | ------------: | --------------- | ---------------- | ----------: | ------------- | ----------- | -----: |
|        101 | 김학생          | kim@example.com  | `010-1111-1111, 02-111-1111` |       201 | 데이터베이스 기초   |      80000 |           301 | 박강사             | park@example.com |         401 | Database      | 2026-08-05  |     90 |
|        101 | 김학생          | kim@example.com  | `010-1111-1111, 02-111-1111` |       202 | Spring 입문   |     100000 |           302 | 이강사             | lee@example.com  |         402 | Spring        | 2026-08-05  | `NULL` |
|        102 | 최학생          | choi@example.com | `010-2222-2222`              |       201 | 데이터베이스 기초   |      80000 |           301 | 박강사             | park@example.com |         401 | Database      | 2026-08-05  |     85 |
|            |              |                  |                              |           |             |            |               |                 |                  |             |               |             |        |

한 학생이 같은 강좌를 한 번만 신청할 수 있으므로 이 테이블의 후보키는 `(student_id, course_id)`라고 가정한다.

## 함수 종속 조건

문제를 풀 때 다음 함수 종속을 사용한다.

```text
student_id → student_name, student_email
course_id → course_name, course_fee, instructor_id, category_id
instructor_id → instructor_name, instructor_email
category_id → category_name
(student_id, course_id) → enrolled_at, score
```

학생의 연락처는 `student_id`에 연결되지만 한 학생이 여러 연락처를 가질 수 있으므로 단일 값 함수 종속으로 취급하지 않는다.

## 풀어야 할 문제

### 1. 이상 현상 찾기

정규화 전 테이블에서 발생할 수 있는 다음 문제를 각각 한 가지 시나리오로 설명한다.

- 삽입 이상
- 갱신 이상
- 삭제 이상

### 2. 제1정규형으로 변환하기

- 1NF를 위반하는 속성을 찾는다.
- 모든 컬럼이 한 행에서 하나의 값만 가지도록 테이블을 분해한다.
- 분해한 각 테이블의 기본키를 표시한다.

### 3. 제2정규형으로 변환하기

- 후보키 `(student_id, course_id)`에 대한 부분 함수 종속을 모두 찾는다.
- 학생 정보, 강좌 정보, 수강 신청 정보를 적절한 테이블로 분리한다.
- 각 테이블의 PK와 FK를 표시한다.

### 4. 제3정규형으로 변환하기

- 일반 속성이 다른 일반 속성을 결정하는 이행 함수 종속을 찾는다.
- 강사와 카테고리 정보를 적절한 테이블로 분리한다.
- 최종 테이블 목록을 `TABLE_NAME(column PK, column FK, ...)` 형식으로 작성한다.

### 5. 관계 확인하기

최종 모델에서 다음 관계의 cardinality를 적는다.

- 학생–연락처
- 학생–수강 신청
- 강좌–수강 신청
- 강사–강좌
- 카테고리–강좌

### 6. SQL로 구현하기

3NF까지 분해한 최종 테이블을 `CREATE TABLE` 문으로 작성한다. 다음 제약을 포함한다.

- 모든 PK와 FK
- 필수 관계의 `NOT NULL`
- 같은 학생이 같은 강좌를 중복 신청하지 못하게 하는 제약
- 점수는 0부터 100까지만 허용하는 `CHECK` 제약

## 완료 기준

- 1NF, 2NF, 3NF마다 제거한 문제를 한 문장으로 설명했다.
- 최종 테이블마다 하나의 주제만 저장한다.
- PK와 FK를 통해 원래 수강 신청 정보를 다시 JOIN할 수 있다.
- 정규화 전 테이블의 중복 학생·강사·카테고리 정보가 최종 구조에서 반복 저장되지 않는다.

## 풀이 시 주의사항

- `enrollment_id` 같은 대체키를 먼저 추가해 부분 함수 종속을 숨기지 않는다. 주어진 후보키 `(student_id, course_id)`를 기준으로 2NF를 판단한다.
- 이 문서에는 정답을 포함하지 않는다. 풀이를 작성한 뒤 [데이터베이스 정규화](./%EB%8D%B0%EC%9D%B4%ED%84%B0%EB%B2%A0%EC%9D%B4%EC%8A%A4%20%EC%A0%95%EA%B7%9C%ED%99%94.md)의 기준과 대조한다.
