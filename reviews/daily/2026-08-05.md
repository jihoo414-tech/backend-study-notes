# 2026-08-05 학습 정리

## 오늘 배운 내용

### 관계형 데이터 모델링과 ERD

업무 파악에서 현실 세계의 요구사항을 찾고, 개념적 모델에서 엔티티·속성·관계를 ERD로 표현한 뒤 논리적 모델과 물리적 모델로 구체화하는 흐름을 학습했다. Chen 표기법에서는 엔티티를 사각형, 관계를 마름모, 속성을 타원으로 나타내지만, 관계는 DB에서 무조건 PK/FK 하나로 바뀌는 것이 아니라 1:N은 주로 외래 키로, M:N은 연결 테이블로 구현된다.

저자와 글은 M:N 관계이므로 `글_저자` 연결 엔티티로 해소할 수 있고, 글과 댓글은 1:N으로 모델링할 수 있다. 관계의 최대 대응 수는 cardinality, 참여의 최소 조건은 optionality로 표현한다. 식별자는 슈퍼키·후보키·기본키·대체키·외래키·복합키로 구분했으며, 자연키와 시스템 생성 대체 식별자는 변경 가능성과 업무상 유일성까지 고려해 선택해야 한다. 자세한 내용은 [관계형 데이터 모델링](../../wiki/database/%EA%B4%80%EA%B3%84%ED%98%95%20%EB%8D%B0%EC%9D%B4%ED%84%B0%20%EB%AA%A8%EB%8D%B8%EB%A7%81.md)에 정리했다.

### 관계 유형을 PK와 FK로 구현하기

- 저자–휴면자는 저자 방향 `0..1`, 휴면자 방향 `1..1`이다. 휴면자는 저자 없이 존재할 수 없으므로 휴면자의 `author_id`를 PK이자 FK로 사용하면 1:1을 구현할 수 있다.
- 글–댓글과 저자–댓글은 1:N이다. N 쪽인 댓글에 `post_id`, `author_id` FK를 두어 댓글 하나가 글 하나와 저자 한 명을 참조하게 한다.
- 저자–글은 M:N이므로 `post_author(post_id, author_id)` 연결 테이블을 둔다. 두 FK를 복합 PK로 사용하면 동일한 저자–글 관계의 중복도 막을 수 있다.

1:1은 FK만으로 최대 한 개라는 조건이 보장되지 않는다. 별도 휴면자 ID를 사용한다면 저자 FK에 `NOT NULL`과 `UNIQUE`가 함께 필요하다. 자세한 SQL 예제와 연결 테이블 데이터는 [관계형 데이터 모델링](../../wiki/database/%EA%B4%80%EA%B3%84%ED%98%95%20%EB%8D%B0%EC%9D%B4%ED%84%B0%20%EB%AA%A8%EB%8D%B8%EB%A7%81.md)에 정리했다.


### Spring Boot 환경별 설정

공통 설정은 `application.yml`에 두고 개발·테스트 환경에서 달라지는 값은 `application-dev.yml`, `application-test.yml`처럼 프로필별 파일로 분리할 수 있다. 이를 통해 같은 애플리케이션 코드에서 데이터소스와 환경 설정을 분리할 수 있다. 자세한 내용은 [Spring Boot 프로필별 설정](../../wiki/spring/Spring%20Boot%20%ED%94%84%EB%A1%9C%ED%95%84%EB%B3%84%20%EC%84%A4%EC%A0%95.md)에 정리했다.

### JPA 질문·답변 연관관계

질문 하나에 여러 답변이 연결되므로 `Question.answers`는 `@OneToMany`, `Answer.question`은 `@ManyToOne`으로 매핑한다. 외래 키가 답변 테이블에 있으므로 `Answer.question`이 연관관계의 주인이며, `Question.answers`는 `mappedBy = "question"`으로 반대편 필드를 지정한다.

DB 반영만 고려하면 `Answer.question`을 설정하고 `answerRepository.save(answer)`를 호출할 수 있다. 이 방식은 외래 키를 저장하지만 현재 Java 객체의 `Question.answers` 컬렉션은 갱신하지 않는다.

Java 객체 관계까지 일치시키려면 `answer.setQuestion(question)`과 `question.getAnswers().add(answer)`를 함께 수행해야 한다. 더 나아가 `Question.addAnswer(content)` 안에서 답변 생성과 양쪽 관계 설정을 처리하면 호출자가 한쪽 설정을 빠뜨리지 않도록 도메인 규칙을 캡슐화할 수 있다. 자세한 비교는 [JPA 일대다 다대일 연관관계](../../wiki/spring/JPA%20%EC%9D%BC%EB%8C%80%EB%8B%A4%20%EB%8B%A4%EB%8C%80%EC%9D%BC%20%EC%97%B0%EA%B4%80%EA%B4%80%EA%B3%84.md)에 연결했다.

### Spring Data JPA 쿼리 메서드

`JpaRepository`가 제공하는 기본 CRUD 외에 도메인 속성으로 조회하려면 Repository 인터페이스에 `findBy...` 규칙을 따르는 메서드를 선언한다. Spring Data JPA는 `By` 뒤의 엔티티 속성과 조건 키워드를 분석해 쿼리를 만든다. 자세한 내용은 [Spring Data JPA 쿼리 메서드](../../wiki/spring/Spring%20Data%20JPA%20%EC%BF%BC%EB%A6%AC%20%EB%A9%94%EC%84%9C%EB%93%9C.md)에 정리했다.

## 핵심 개념 연결

```text
업무 규칙
  -> 개념 ERD의 엔티티·속성·관계
  -> 1:1은 FK + UNIQUE, 1:N은 N 쪽 FK, M:N은 연결 테이블
  -> 논리 모델의 키·외래 키·정규화
  -> 물리 모델의 자료형·인덱스·DBMS 세부 설정

Spring Boot 프로필
  -> 개발 DB와 테스트 DB 설정 분리

Question 1 : N Answer
  -> DB 외래 키는 Answer가 관리
  -> JPA 연관관계의 주인은 Answer.question
  -> Java 객체 그래프는 Question.answers까지 함께 동기화
  -> Question.addAnswer()로 관계 설정 책임 캡슐화

Repository 조회
  -> 엔티티 속성 기반 파생 쿼리
  -> 단건 조회 결과의 부재는 Optional과 연결
```

## 기존 지식과의 연결

- [관계형 데이터 모델링](../../wiki/database/%EA%B4%80%EA%B3%84%ED%98%95%20%EB%8D%B0%EC%9D%B4%ED%84%B0%20%EB%AA%A8%EB%8D%B8%EB%A7%81.md)의 1:N 관계는 외래 키를 거쳐 JPA의 `@ManyToOne` 및 `@OneToMany` 매핑으로 이어진다.
- 저자와 글의 M:N 연결 엔티티는 이후 [데이터베이스 정규화](../../wiki/database/%EB%8D%B0%EC%9D%B4%ED%84%B0%EB%B2%A0%EC%9D%B4%EC%8A%A4%20%EC%A0%95%EA%B7%9C%ED%99%94.md)와 복합키 학습의 예제가 된다.
- [Spring Boot 프로필별 설정](../../wiki/spring/Spring%20Boot%20%ED%94%84%EB%A1%9C%ED%95%84%EB%B3%84%20%EC%84%A4%EC%A0%95.md)은 개발 환경과 테스트 환경의 DB를 격리하는 기반이 된다.
- [JPA 일대다 다대일 연관관계](../../wiki/spring/JPA%20%EC%9D%BC%EB%8C%80%EB%8B%A4%20%EB%8B%A4%EB%8C%80%EC%9D%BC%20%EC%97%B0%EA%B4%80%EA%B4%80%EA%B3%84.md)는 관계형 DB의 외래 키를 Java 객체 참조로 표현한다.
- `Question`과 `Answer`의 1:N 관계는 [데이터베이스 정규화](../../wiki/database/%EB%8D%B0%EC%9D%B4%ED%84%B0%EB%B2%A0%EC%9D%B4%EC%8A%A4%20%EC%A0%95%EA%B7%9C%ED%99%94.md)와 외래 키 학습으로 이어진다.
- `findById()`와 파생 쿼리의 단건 결과 처리는 [Optional](../../wiki/java/Optional.md) 학습과 연결된다.

## 프로젝트 적용

- 진행 중인 질문·답변 프로젝트에서 질문과 답변 엔티티의 1:N 관계를 구현하는 데 적용한다.
- 답변 생성 책임을 `Question.addAnswer()`에 두면 연관관계 설정 규칙을 도메인 내부에 모을 수 있다.
- 실제 저장 동작은 트랜잭션과 cascade 설정을 함께 확인해야 한다.
