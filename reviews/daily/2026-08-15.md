# 2026-08-15 일일 학습 리뷰

## 오늘 달라진 점

정렬된 두 배열을 단순히 합쳐 다시 정렬하지 않고, 입력의 정렬 상태를 활용해 투 포인터로 선형 시간에 병합하는 문제를 풀었다.
고정된 길이의 연속 매출 구간에서는 이전 구간 합을 재사용하는 슬라이딩 윈도우로 중복 계산을 제거했다.

## 새로 설명할 수 있게 된 것

- 투 포인터 선택의 핵심은 배열 개수가 아니라 정렬 또는 단조성을 이용해 지나간 범위를 다시 볼 필요가 없다는 점이다.
- 각 배열의 현재 원소 중 작은 값이 남은 원소 전체의 최솟값이라는 사실로 선택을 확정할 수 있다.
- 합친 뒤 정렬하는 방식과 투 포인터 병합의 차이를 각각 `O((N + M) log(N + M))`, `O(N + M)`으로 설명할 수 있다.
- `연속된 K개`와 인접 구간의 중복을 슬라이딩 윈도우 선택 신호로 설명할 수 있다.
- 완전 탐색 `O(NK)`, 누적 합 `O(N)`, 슬라이딩 윈도우 `O(N)`의 시간·공간 차이를 구분할 수 있다.

## 직접 구현하거나 검증한 것

- `p1`, `p2`로 두 배열의 미처리 첫 원소를 비교하고 선택한 쪽의 포인터를 이동하는 코드를 작성했다.
- 한 배열을 모두 처리한 뒤 다른 배열의 남은 값을 결과에 추가했다.
- 사용자가 플랫폼 제출 성공을 보고했다.
- 첫 `K`개 매출 합을 만든 뒤 `arr[i] - arr[i-K]`를 반영해 각 창의 합을 `O(1)`에 갱신하는 코드를 작성했다.
- 슬라이딩 윈도우 코드를 Java 25 JShell에서 예제 입력으로 실행해 출력 `56`을 확인했다.
- PBL mission-05를 완료했다. 세부 구현은 별도로 정리하지 않고 다형성·인터페이스·전략 패턴을 설계한 미션이라는 사실만 기록했다.

## 기존 지식과의 연결

mission-04에서 `ArrayList`는 등록 순서 보존을 위한 결과 컬렉션으로 선택했다. 이번 문제에서도 결과 순서를 유지하는 `ArrayList`를 사용했지만, 알고리즘의 핵심은 컬렉션 종류가 아니라 정렬된 두 입력을 각각 한 방향으로 순회하는 방식이다.

투 포인터 병합과 슬라이딩 윈도우는 모두 포인터를 되돌리지 않고 이전 계산을 재사용해 선형 시간에 처리한다. 투 포인터는 비교 결과에 따라 한쪽 포인터를 이동하고, 고정 길이 창은 양쪽 경계를 같은 간격으로 이동한다.
