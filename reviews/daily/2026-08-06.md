# 2026-08-06 학습 정리

## 오늘 배운 내용

- JPA 더티 체킹은 영속성 컨텍스트가 관리 중인 엔티티의 변경을 감지하고 flush 시 데이터베이스와 동기화하는 기능이다.
- `CascadeType.PERSIST`는 더티 체킹 자체가 아니라 부모의 persist 작업을 새 자식 엔티티에 전파하는 생명주기 규칙이다.
- 양방향 `OneToMany` 관계에서는 컬렉션 추가와 함께 외래 키를 관리하는 연관관계의 주인도 설정해야 한다.
- Spring Bean은 `@Configuration`의 `@Bean` 메서드로 명시적으로 등록하거나, `@Component` 계열 클래스를 컴포넌트 스캔으로 탐지하여 등록할 수 있다.
- `@Bean` 방식은 생성 인자와 구현체를 직접 선택하거나 같은 타입을 여러 구성으로 등록하기 쉽고, 컴포넌트 스캔은 애플리케이션 클래스의 반복 설정을 줄인다.
- 필드의 `@Autowired`는 객체 생성 후 값을 주입하지만, `final` 필드와 Lombok `@RequiredArgsConstructor` 조합은 생성된 생성자를 통해 객체 생성 시 의존성을 받는다.
- `ApplicationRunner` 구현체가 Spring 빈이면 Spring Boot가 컨텍스트 준비 후 해당 타입의 빈을 찾아 `run(ApplicationArguments)`을 호출한다.
- `self`와 주입 지점의 `@Lazy`는 자기 자신의 프록시를 늦게 주입받아 `this` 내부 호출이 우회하는 AOP 프록시를 경유하려는 방법으로 사용될 수 있다.

## 핵심 개념 연결

`@Transactional`로 트랜잭션 시작 → 엔티티가 관리 상태로 유지 → 엔티티와 연관관계 변경 → 커밋 전 flush → 기존 엔티티 변경은 `UPDATE`, cascade persist가 적용된 새 엔티티는 `INSERT`

`@Configuration`·`@Bean` 또는 컴포넌트 스캔 → 빈 정의 등록 → Spring이 생성자를 선택하고 의존성을 전달 → 초기화된 빈을 컨테이너가 관리 → 컨텍스트 준비 후 `ApplicationRunner` 빈의 `run` 호출

## 기존 지식과의 연결

- 질문–답변 양방향 관계에서 `Question.answers` 컬렉션과 `Answer.question` 연관관계의 주인을 함께 설정해야 객체 그래프와 DB 외래 키 관계가 일치한다.
- Spring AOP 프록시는 `@Transactional` 메서드의 트랜잭션 경계를 만들고, JPA 영속성 컨텍스트가 그 범위에서 변경을 추적하고 flush한다.
- Bean 등록 방식과 의존성 주입 방식을 서로 다른 축으로 구분했다. `@Bean` 대 `@Component`는 **무엇을 빈으로 등록할지**의 문제이고, 필드 주입 대 생성자 주입은 **필요한 빈을 어떻게 전달할지**의 문제다.
- 수업에서 들은 “`@RequiredArgsConstructor`는 완전히 만든 후 주입한다”는 표현은 정확하지 않다. 이 애너테이션이 만든 생성자를 Spring이 호출할 때 의존성이 함께 전달된다.

## 프로젝트 적용

- `Question.addAnswer`만으로 새 답변이 저장되는지는 실제 cascade 설정, 연관관계의 주인 설정과 트랜잭션 범위를 확인해야 한다.

## 다시 확인할 내용

- `CascadeType.PERSIST`가 없는 경우와 있는 경우의 `INSERT` 차이
- 관리 상태와 분리 상태에서 필드 변경 후 `UPDATE` 발생 여부
- AOP 프록시를 거치지 않는 내부 호출에서 `@Transactional`이 적용되지 않는 경우
- 수업 코드에서 `self`로 호출한 실제 메서드와 적용된 AOP 애너테이션
- `ApplicationRunner`가 수업 예제에서 맡았던 초기화 작업과 실행 결과
- 프록시에 관한 나머지 수업 설명. AOP는 오늘 진행하지 않았으므로 완료 학습으로 기록하지 않음

## 후속 학습 연결

- 트랜잭션 경계, flush 시점, 더티 체킹과 cascade persist가 협력하는 순서를 예제와 SQL 로그로 추가 확인할 예정이다.
- 무료 한국어 자료로 `ApplicationRunner`와 `CommandLineRunner`의 인자 차이, Runner 수집·실행 흐름을 복습한다.
