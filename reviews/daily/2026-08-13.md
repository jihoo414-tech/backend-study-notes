# 2026-08-13 학습 정리

## 오늘 배운 내용

- 틀렸던 코딩테스트 문제 중 배열 부분을 복습했다.
- 임시 반장 정하기와 멘토링 문제는 아직 약한 문제로 확인해 별도로 기록했다.
- PBL mission-03 Attendance Manager를 완료했다. 대부분의 구현은 ChatGPT의 도움을 받았으며, 구현 전에 요구사항에 맞는 자료구조를 선택하는 중요성을 학습했다.

## 핵심 개념 연결

- 임시 반장 문제는 후보 학생과 다른 학생을 비교하여 5개 학년 중 같은 반이었던 적이 한 번이라도 있는지 판정한다. 여러 학년에서 만났더라도 한 사람은 한 번만 세는 것이 핵심이다.
- 멘토링 문제는 가능한 멘토·멘티 쌍마다 모든 시험에서 멘토의 순위가 앞서는지 판정한다. 입력 배열의 값은 학생 번호이고, 그 값이 놓인 위치가 순위라는 점을 구분해야 한다.
- 두 문제 모두 학생 쌍을 완전 탐색하지만, 임시 반장은 일치를 발견하면 성공하고 멘토링은 불일치를 발견하면 실패한다.
- mission-03에서는 `date + memberEmail`이 한 출석 기록의 고유 식별자이며, 동일 식별자의 출석 여부를 덮어써야 한다. 따라서 `Map<AttendanceKey, Boolean>`의 키 조회와 `put` 동작이 요구사항에 잘 맞는다.

## 기존 지식과의 연결

- [2차원 배열의 학생 관계 비교](../../wiki/algorithm/2%EC%B0%A8%EC%9B%90%20%EB%B0%B0%EC%97%B4%EC%9D%98%20%ED%95%99%EC%83%9D%20%EA%B4%80%EA%B3%84%20%EB%B9%84%EA%B5%90.md)에 배열 축의 의미, 존재·전체 조건, 조기 종료와 시간 복잡도를 함께 정리했다.
- [에라토스테네스의 체](../../wiki/algorithm/%EC%97%90%EB%9D%BC%ED%86%A0%EC%8A%A4%ED%85%8C%EB%84%A4%EC%8A%A4%EC%9D%98%20%EC%B2%B4.md)에서 배열 인덱스와 상태를 대응했던 것처럼, 이번에는 인덱스가 학생·학년·시험·순위 중 무엇을 뜻하는지 먼저 고정해야 한다.
- [List와 Map 선택 기준](../../wiki/java/List%EC%99%80%20Map%20%EC%84%A0%ED%83%9D%20%EA%B8%B0%EC%A4%80.md)을 통해 자료의 단순함보다 주요 연산, 고유 키, 중복과 순서 요구사항으로 컬렉션을 선택해야 한다는 점을 보완했다.

## 프로젝트 적용

- [mission-03 Attendance Manager](../../wiki/projects/mission-03%20Attendance%20Manager.md)에서 복합 키를 `record`로 만들고, 이를 `HashMap` 키로 사용해 출석 여부를 등록·조회했다.
- 파일 로딩은 임시 Map에서 전체 검증을 마친 뒤 기존 상태를 교체하여 잘못된 파일이 메모리 상태를 부분 변경하지 않도록 구현되어 있다.

## 다시 확인할 내용

- 실제 풀이 코드가 없어 두 문제에서 구체적으로 막힌 지점은 아직 확인되지 않았다.
- 임시 반장에서 같은 학생을 여러 번 세지 않는 위치와 동점일 때 작은 번호를 유지하는 갱신 조건을 다시 확인한다.
- 멘토링에서 학생 번호와 순위 인덱스를 구분하고, 직접 위치를 찾는 방식과 순위 역매핑 방식의 복잡도를 비교한다.
- 처음 시도한 `ArrayList` 코드는 남아 있지 않아 구체적으로 어느 로직에서 실패했는지는 확인되지 않았다.
- ChatGPT 도움으로 작성된 `record` 복합 키와 임시 Map 기반 `load`를 스스로 설명하고 다시 구현할 수 있는지 확인한다.

## 후속 학습 연결

- 두 문제를 다시 풀 때 반복문마다 순회 대상과 종료 조건을 한 문장으로 적고, 풀이 후 시간 복잡도를 입력 제한에 대입해 본다.
- mission-03을 다시 구현하며 `List`를 쓸 경우 필요한 선형 검색과 중복 방지 분기를 `Map` 구현과 비교한다.
- 오늘 보려던 Java `record`, Spring AOP, DDD, Tomcat, API 버저닝 자료는 시간이 많이 필요해 시청하지 못했다. 완료 학습으로 기록하지 않고 [오늘 계획의 주말 확인 자료](../../planner/daily/2026-08-13.md)에 보존했다.
- Java `record` 자료는 mission-03의 `AttendanceKey`, Spring AOP 자료는 기존 [Spring Bean 등록과 의존성 주입](../../wiki/spring/Spring%20Bean%20%EB%93%B1%EB%A1%9D%EA%B3%BC%20%EC%9D%98%EC%A1%B4%EC%84%B1%20%EC%A3%BC%EC%9E%85.md)의 프록시 내용과 직접 연결한다. 나머지 주제는 시청 후 실제 학습 범위를 확인한다.
