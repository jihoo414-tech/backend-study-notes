# 2026-08-20 일일 학습 리뷰

## 오늘 달라진 점

- 쉬운코드 데이터베이스 재생목록으로 데이터베이스 학습을 시작했다.
- BJ.35 관계형 데이터베이스 영상을 시청하고 relation, tuple, attribute, domain과 여러 key 용어를 기초 수준에서 확인했다.
- 프로그래머스 `같은 숫자는 싫어`를 Stack으로 풀고, 같은 연산을 List로 표현하는 방법을 비교했다.
- 괄호, 올바른 괄호 사용, 괄호 제거 후 문자 출력과 같은 기본 문제를 추가로 풀어 오늘의 스택 문제 학습을 완료했다.
- 사용자 보고 기준으로 PBL mission-09를 완료했다.
- 사용자 보고 기준으로 Spring Validation을 사용한 PBL mission-10을 완료했다.

## 새로 설명할 수 있게 된 것

- 관계형 데이터베이스에서 relation을 행과 열로 구성된 테이블 형태로 이해하고, 행을 tuple, 이름이 붙은 속성을 attribute로 부르는 기본 용어
- 행을 유일하게 식별하는 super key, 최소성을 만족하는 candidate key, 대표로 선택한 primary key와 다른 relation을 참조하는 foreign key의 기초적인 구분
- 모든 중복을 제거하는 것과 연속 중복만 제거하는 것이 다르며, 결과의 마지막 값과 현재 값을 비교하면 입력 순서를 보존할 수 있는 이유
- Stack으로도 풀 수 있지만 LIFO 제거가 필요하지 않고 마지막 값 확인·끝 추가·순서 접근이 중심이므로 List가 더 자연스러운 이유

## 직접 구현하거나 검증한 것

- 사용자가 영상을 시청하고 이해한 내용을 직접 작성했다.
- 별도의 SQL 작성, 데이터베이스 실행, 예제 검증은 하지 않았다.
- 사용자가 `Stack<Integer>`를 이용한 `같은 숫자는 싫어` 풀이 코드를 작성했다.
- Java 25.0.2 JShell에서 Stack 풀이와 List 풀이를 공개 예제 두 건, 길이 1, 모두 다른 값, 모두 같은 값으로 실행해 같은 결과를 확인했다.
- 괄호 관련 기본 스택 문제의 완료 사실은 사용자 보고로 확인했으며, 별도 코드나 제출 결과는 제공되지 않았다.
- PBL mission-09의 완료 사실은 사용자 보고로 확인했으며, 구현 코드와 테스트 결과는 제공되지 않았다.
- PBL mission-10의 완료 사실과 Spring Validation 사용은 사용자 보고로 확인했으며, 구현 코드와 테스트 결과는 제공되지 않았다.

- 기존 Wiki에는 super key, candidate key, primary key, alternate key, foreign key와 composite key의 구분이 이미 정리되어 있다. 이번 영상은 해당 용어를 쉬운 설명으로 다시 접한 입문 기록으로 연결한다.
- relation의 attribute와 원자성은 이후 [데이터베이스 정규화](../../wiki/database/%EB%8D%B0%EC%9D%B4%ED%84%B0%EB%B2%A0%EC%9D%B4%EC%8A%A4%20%EC%A0%95%EA%B7%9C%ED%99%94.md)의 1NF를 학습할 때 다시 연결할 수 있다.
- [List와 Map 선택 기준](../../wiki/java/List%EC%99%80%20Map%20%EC%84%A0%ED%83%9D%20%EA%B8%B0%EC%A4%80.md)의 `주요 연산을 기준으로 선택한다`는 원칙을 Stack과 List 비교에도 적용했다.

## 아직 설명하거나 검증하지 못한 것

- 원본의 `자료를 받은 날짜`는 2026-08-19이지만 현재 대화와 학습 기록일은 2026-08-20이므로 실제 시청일 확인이 필요하다.
- 이론 용어인 alternate key와 SQL의 `UNIQUE` 제약·unique key를 항상 같은 뜻으로 볼 수 있는지는 DBMS별 `NULL` 처리까지 포함해 구분할 필요가 있다.
- attribute의 원자성은 값을 무조건 의미 단위로 모두 분리한다는 뜻인지, 해당 도메인에서 하나의 값으로 취급되는지에 따라 달라질 수 있어 주소 예시는 후속 정규화 학습에서 다시 확인해야 한다.
- 영상의 설명을 공식 명세나 DBMS 동작으로 별도 검증하지 않았다.
- `같은 숫자는 싫어`의 제출 결과가 비어 있어 프로그래머스 전체 테스트 통과 여부는 확인하지 못했다.
- Raw의 `원본 문제`에는 이전의 카드 세 장 합 문제가 섞여 있으며, 공식 문제는 `입력` 아래의 연속 중복 제거 문제로 확인했다.
- 추가 괄호 문제의 정확한 문제명·플랫폼·코드·제출 결과는 제공되지 않아 상세 동작과 통과 여부를 검증하지 않았다.
- PBL mission-09의 요구사항·구현 범위·테스트 통과 여부는 제공되지 않아 완료 보고 외의 내용은 검증하지 않았다.
- PBL mission-10에서 사용한 Validation 제약 조건, `@Valid`·`@Validated` 적용 위치, 검증 실패 응답과 테스트 결과는 제공되지 않아 검증하지 않았다.
