# 2026-08-19 일일 학습 리뷰

## 오늘 달라진 점

- 사용자가 오늘 계획의 필수 학습을 모두 완료했다고 보고했다.
- 점프 투 스프링부트 2장까지 진행해 질문 생성과 답변 등록을 구현했다.
- 프로그래머스 최소직사각형 문제에서 각 명함의 회전 여부를 모두 열거하지 않고, 각 행을 `(긴 변, 짧은 변)`으로 통일해 탐색 공간을 제거하는 발상을 학습했다.
- 문제의 완전탐색 분류가 가능한 모든 조합을 반드시 코드로 생성하라는 뜻은 아니며, 대칭과 독립성을 찾으면 하나의 표준 상태로 축약할 수 있음을 확인했다.
- 세 카드 인덱스 조합을 모두 생성하고 TreeSet으로 중복 합 제거와 내림차순 정렬을 동시에 처리하는 풀이를 학습했다.

## 새로 설명할 수 있게 된 것

- 명함마다 회전 선택이 두 가지여도 가로·세로 축의 이름은 교환 가능하므로 모든 명함의 긴 변을 한 축으로 통일할 수 있는 이유
- 정규화 후 긴 변들의 최댓값과 짧은 변들의 최댓값이 각각 모든 가능한 지갑이 만족해야 하는 하한이 되는 이유
- `Math.min()`으로 각 명함의 짧은 변을 구한 다음에도 전체 집계에서는 최댓값을 구해야 하는 이유
- 모든 회전 조합 `2^N`을 한 번의 선형 순회 `O(N)`으로 줄이는 사고 과정
- `i < j < l`이 같은 카드 선택과 순서만 다른 중복 조합을 제거하는 이유
- HashSet은 빠른 존재 확인, TreeSet은 중복 제거와 정렬·범위 탐색, Map은 키별 값·빈도 저장에 사용하는 기준
- 카드 합 풀이의 시간 복잡도가 `O(N)`이 아니라 `O(C(N,3) log M)`인 이유

- 사용자 보고 기준으로 점프 투 스프링부트 2장의 질문 생성과 답변 등록 기능을 구현했다. 이번 입력에는 코드와 실행·테스트 결과가 포함되지 않아 직접 검증하지 않았다.

- 사용자가 제공한 Java 코드는 각 명함의 긴 변과 짧은 변을 구하고 각 축의 최댓값을 곱하는 방식이다.
- Java 25.0.2 JShell에서 공개 예제 세 건을 실행해 출력 `4000`, `120`, `133`을 확인했다.
- 변수 `minH`가 실제로 짧은 변들의 최댓값을 저장하므로 `maxShort`가 더 정확한 이름임을 확인했다.
