# 2026-08-14 일일 학습 리뷰

## 오늘 달라진 점

- PBL mission-04 Library Rental을 완료했다는 사용자 보고를 기록했다.
- 도서 등록 순서를 유지해 전체 목록을 반환해야 하는 요구사항을 근거로 `Map`과 `ArrayList`를 비교하고 `ArrayList`를 선택했다.
- 현재 구현과 public 테스트를 직접 확인해 계획의 mission-04 항목을 완료로 갱신했다.

## 새로 설명할 수 있게 된 것

- 요구사항에 순서 보존이 포함됐다는 사실만 보는 것이 아니라 주요 연산, 데이터 규모, 조회 비용을 함께 고려해 자료구조를 선택해야 한다.
- 도서는 `대출 가능 → 대출 중 → 반납 완료`로 상태가 변하며, 잘못된 상태 전이는 `IllegalStateException`으로 거부할 수 있다.
- 존재하지 않는 식별자와 잘못된 입력은 각각 `NoSuchElementException`과 `IllegalArgumentException`으로 구분한다.

## 직접 구현하거나 검증한 것

- 실제 구현에서 `registerBook`, `rentBook`, `returnBook`, `getBook`, `getAllBooks`를 확인했다.
- `ArrayList`에 등록 순서대로 도서를 추가하고 `new ArrayList<>(bookList)`로 목록 복사본을 반환하는 구현을 확인했다.
- 2026-08-14에 `starter`에서 `gradlew.bat test --console=plain`을 실행해 public 테스트의 `BUILD SUCCESSFUL`을 확인했다.

## 기존 지식과의 연결

mission-03에서는 `date + memberEmail` 복합 키로 조회하고 같은 키의 값을 덮어쓰는 연산이 중심이어서 `Map`이 적합했다. mission-04에서는 등록 순서대로 전체 도서를 반환하는 요구와 단순한 미션 규모를 고려해 `ArrayList`를 선택했다. 다만 단건 조회는 선형 탐색이므로 데이터가 커지면 `LinkedHashMap<Long, Book>`도 비교 대상이 된다.

## 프로젝트 적용

- 도서의 `rented`와 `renter`를 함께 변경해 대출 상태의 일관성을 유지했다.
- 중복 대출과 미대출 도서 반납을 상태 전이 오류로 처리했다.
- 사용자가 프로젝트 Wiki 작성을 요청하지 않았으므로 `wiki/projects/` 문서는 만들지 않았다.

## 아직 설명하거나 검증하지 못한 것

- 체크인된 public 테스트는 `registerBook(null)`의 예외만 직접 확인한다. 숨겨진 테스트의 전체 통과 여부는 검증하지 못했다.
- `Book`에 Lombok `@Setter`가 있어 서비스 외부에서도 상태를 변경할 수 있다. 이는 “도메인 상태 변경은 `LibraryService`의 공개 메서드로만 수행” 제약과 충돌할 가능성이 있어 검증이 필요하다.
- 제출 원본의 `내가 실제로 수행한 내용`과 테스트 결과는 비어 있으므로 세부 구현 과정은 추정하지 않았다.
